1. Skill 架构

OneDZ Skill 由文档层、模板层、API 层三层组成，AI 按优先级逐层调用

📄

SKILL.md / SKILL_ZH.md

Skill 入口文件。AI 每次收到用户请求时首先读取此文件，获取 6 步工作流程和 API 使用规则。

📑

examples_index.md

Example 快速匹配表。根据用户需求关键词，匹配最合适的代码模板（如 regional_comparison）。

💻

examples/*.py

可复用代码模板。regional_comparison.py、grouped_comparison.py 等，AI 复制后修改参数即可。

📊

onedz_dataset_structure.json

轻量级数据索引（~50KB）。无需加载 1.5GB 数据即可查询可用国家、时期、岩石类型等。

🔧

OneDZHandler API

核心 Python API。query()、clean()、analyze()、ks_test()、plot_age() 等。

📖

references/

API 文档层。包含 api_reference.md、quick_reference.md、workflows.md 等。

2. 工作流程

当用户输入分析请求后，AI 严格按照以下 6 步执行

创建任务工作目录

每次分析任务创建独立文件夹，脚本和输出全部隔离，避免不同任务混在一起。

Python
TASK_DIR = Path.cwd() / "china_vs_india_20260422" TASK_DIR.mkdir(parents=True, exist_ok=True) config = OneDZConfig(output_dir=TASK_DIR, use_timestamp_output=False)

查找匹配 Example

读取 examples_index.md 的快速匹配表，找到最相关的代码模板。

AI 内部操作：查找 examples_index.md
# 快速匹配表（节选） # ┌──────────────────────┬──────────────────────────┐ # │ 用户需求 │ 最佳 Example │ # ├──────────────────────┼──────────────────────────┤ # │ 对比两个区域 │ regional_comparison │ # │ 按时期/岩石类型分组 │ grouped_comparison │ # │ 年龄分布 + 峰值检测 │ age_distribution │ # │ Lu-Hf 同位素 │ luhf_analysis │ # │ 基础查询 │ basic_query │ # └──────────────────────┴──────────────────────────┘

查询数据可用性（可选）

不确定参数是否存在时，读取 onedz_dataset_structure.json（~50KB），无需加载 1.5GB 数据。

AI 内部操作：确认数据集中有 "India"
import json with open("onedz_dataset_structure.json") as f: ds = json.load(f) countries = ds["quick_index"]["Country_State"]["categories"] # 找到: "India" 存在 ✅ （共 206 个国家/地区） # 找到: "China" 存在 ✅

查阅 API 文档（如需）

Example 模板不够用时，按 quick_reference.md → api_reference.md 顺序查找。大多数情况下 Example 已足够，此步可跳过。

生成代码 & 执行

基于 Example 模板复制修改参数，生成完整 Python 脚本，写入任务目录后执行。AI 遵循严格的 API 规范。

核心 API 调用模式
handler = OneDZHandler(config=config) handler.load(source="csv", table="global_u-pb") df = handler.query(country_state="China") # ✅ 正确参数名 if df.height == 0: # ✅ 检查空数据 return df_clean = handler.clean(df, concordance_min=0.90) result = handler.analyze(df_clean) handler.plot_age(df_clean, mode="kde", save="kde.png")

输出结果

所有图表（PNG）和数据（CSV）保存到任务目录。AI 从运行输出中提取结论，禁止编造未运行的结果。

analysis.py
# 初始化 config = OneDZConfig(output_dir=TASK_DIR, use_timestamp_output=False) handler = OneDZHandler(config=config) handler.load(source="csv", table="global_u-pb") # 查询 China df_china = handler.query(country_state="China") df_china_clean = handler.clean(df_china, concordance_min=0.90) ages_china = df_china_clean["Best Age"].drop_nulls().to_numpy() # 查询 India df_india = handler.query(country_state="India") df_india_clean = handler.clean(df_india, concordance_min=0.90) ages_india = df_india_clean["Best Age"].drop_nulls().to_numpy() # K-S 检验 ks = handler.ks_test(ages_china, ages_india, alpha=0.05) print(f"D-statistic: {ks['statistic']:.4f}") # ✅ 正确键名 print(f"p-value: {ks['p_value']:.4e}") # 可视化 handler.plot_multi_kde( {"China": ages_china, "India": ages_india}, age_range=(0, 4000), save="china_india_comparison.png" )

3. 设计原则

Skill 的核心设计理念，确保 AI 生成代码的准确性和可靠性

复用 > 修改 > 重写

AI 优先从已有 Example 模板复制代码，只修改参数部分。从零编写只在无任何模板匹配时才使用。

轻量级数据预检

通过 onedz_dataset_structure.json（50KB）确认参数是否存在，避免加载 1.5GB 数据后才发现国家名拼错。

防错机制

强制检查 df.height > 0，使用正确的列名 "Best Age"、正确的键名 'statistic'，避免常见 API 陷阱。

任务隔离

每次分析创建独立目录，脚本、图表、数据全部保存在内。不同任务互不干扰。

禁止编造结论

所有分析结论必须来自脚本实际运行输出。未运行不编造，结果异常如实报告。

文档优先级

查找顺序: examples_index.md → examples/*.py → quick_reference.md → api_reference.md。层级越浅优先级越高。

效果对比

Before (无 Skill 指南)

AI 凭记忆生成代码
↓ 参数名错误: countries vs country_state
↓ 返回值错误: d_statistic vs statistic
↓ 列名错误: BestAge vs Best Age
↓ 多次迭代修正，~16 分钟

After (使用 Skill 指南)

AI 查 Example 模板 → 复制修改
↓ 参数名从模板获取: country_state ✓
↓ 返回值从模板获取: statistic ✓
↓ 列名从模板获取: "Best Age" ✓
↓ 一次成功，~5 分钟
